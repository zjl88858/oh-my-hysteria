# NetFront 候选发布验证

这是手动 QA，不在 CI 中连接公网。对照是同一构建中用户可以直接选择的 Presto；NetFront 的主路密钥另行派生，因此不是仅开关副路、其他字节逐位相同的消融实验。

## 2026-11-20 预定方案

- Windows → 同一 Linux IPv4 VPS、同一主端口、正常 TLS、BBR standard；每次新开进程、独立冷连接。三份独立随机口令 A/B/C，每份重复两轮；六个区组各跑 Presto、NetFront 两副路、NetFront 三副路一次，用三种模式的全部六种排列平衡先后顺序。共 18 次短测。另以同一密钥分别跑一次 Presto 和三副路的约 27 秒活动负载，跨过 NetFront 的 20 秒最长路径许可。短测、长测和早先的冒烟结果分别分析。
- 每连接在**同一个 TCP 流**上先后回显 8 KiB + 8 KiB 随机数据，夹在两次回显之间的是 72 条（长测 180 条）大小为 16～1056 B 的 UDP 消息。客户端边发边收；每条有本次随机标记、序号和可独立校验的内容。最后一条发送后留 2 秒收尾窗口，不重发，不挑结果。保留客户端发送、VPS 回显端收到、VPS 成功回写、客户端收到四个有序序号列表及重复/损坏计数。两个方向的缺失指观测点之间，不能直接算作某个物理端口的网络丢包率。
- 内核过滤器只取测试端口；只保存各方向、各端口的长度计数和认证后的副包类型/许可代号，不保存载荷或密码。公网账本从本台新 VPS 既有回执开始累计；这组实验在累计 4.5 MiB 前提前停止，硬线 6 MiB / 300 秒。SSH 准备、Linux 回环、开发机回环不在公网代理 UDP 口径内。一次样本或整个批次失败都记录，不用一次额外成功替换它。
- **可选实验功能的验收线（不是性能非劣证明）：** 所有计划样本均有有效计数、正常 TLS、同流 TCP 两段内容正确；无数据损坏、意外重复、回显应用写失败或抓包丢弃。各次主端口双向包数均占多数；每条配置副路均完成双向证明，副包不超过 384 B。两种 NetFront 配置分别在汇总中有双向真实数据。长测各副路须在新代号下再次成功往返。短测任一 NetFront 样本回显低于 90%，或一种 NetFront 的总体回显率比 Presto 低超过 2 个百分点，则暂不建议发布；若 Presto 样本本身低于 90%，线路对照不足。样本级结果、方向分解和长测另报，不以合并平均数掩盖异常。
- 补充受控验证包括无注入丢包四点校准、不同延迟、在途跨续期与原地址失效、侧路受阻及恢复、十分钟发送会话轮换。没有游戏流量分类真值，不把互通验证写成抗识别结论。

`common.py` 定义配对顺序、消息和四点分析；`client.py` 只向本机转发口提交应用消息；`endpoint.py` 在 Linux 运行同一候选、仅允许出站到本机两个回显服务。`wire.py` 负责按端口计量。结果 JSON 不含远程登录信息。
