# PrestoLite：单端口的大流轻量模式

从 [v1.3.1](release-v1.3.1.md) 起可选。PrestoLite 在连续传文件时会跳过部分原定停顿。它保留 [Presto](presto.md) 的前导、逐片认证、全程四状态包长、分片和随机填充，但**降低了持续大流的时序混淆**。如果希望保持标准版的突发节奏，应选择 `presto`。

## 配置

两端都配置：

```yaml
obfs:
  type: prestolite
  prestolite:
    password: "REPLACE-WITH-AT-LEAST-32-RANDOM-BYTES"
```

`password` 是唯一选项，32～1024 个 UTF-8 字节，使用与代理 `auth` 不同的随机秘密。使用固定 UDP 端口，保持正常 TLS 校验和两端时钟同步。分享链接用 `obfs=prestolite`、`obfs-password`。`presto`、`prestolite`、`netfront`、`netfrontlite` 是四种不同类型，同一密码也不能跨类型连接；没有自动协商、回退或 `profile: lite` 配置。

## 何时减少等待

对每个发送会话、每个方向单独判断：

- 只有至少 1000 字节的内层 QUIC 短头数据报计入大流。前 32 KiB 合格输入按原策略发送；遇到长头，或合格大包间隔超过 40 ms，重新预热。小包自己产生的计划停顿照常执行。
- 预热后，每输入 1 KiB 合格数据累积 80 微秒的**计划停顿额度**，最多存 2.5 ms。仍对每片调用原采样器：余额够就执行原时长并扣除，不够就跳过。不是每 KiB 强制等待 80 微秒，也不会把欠下的等待留到空闲时补发。
- 密码和角色仍按原规则决定包长与状态转移。会话独立采样，内层最多 1200 B、主路外包最多 1232 B，每片固定封装 84 B。减少的是等待，不是这些字节成本。

## 已建立端点的接收额度

同一 IP 和 UDP 端口的当前会话，只有在收齐新的、通过认证和重放检查、已交给上层的大短头数据报后，才能按真实片数获得额度。第一次建立路由、残片、重放、无业务包和输出缓冲区过小都不增加额度。

每个端点最多保留 256 片额度，距上次合格交付 250 ms 即失效。支用仍受来源分桶的附加上限（16384 片/秒，突发 256）和原来的全局上限（32768 片/秒，突发 4096）约束；原来源桶为 8192 片/秒，突发 2048。不向共享来源桶返还额度，同 IP 上的另一个端口不能借用。额度只允许多尝试处理下一片，**每片仍需独立通过 AEAD**。会话准入和重组上限不变。

认证沿用 XChaCha20-Poly1305 和 Presto v1 帧布局，HKDF 的认证标签为 `lite/aead/client-to-server`、`lite/aead/server-to-client`，包长派生仍为 `genome/<方向>`。因此标准版和 Lite 可做同密码的包长规则对照，但不能交换认证帧。回环吞吐能验证速度和正确性，不能测出识别率或封锁率。
