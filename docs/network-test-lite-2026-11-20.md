# PrestoLite / NetFrontLite：同密码文件吞吐对照（2026-11-20）

以下吞吐对照使用 `v1.3.0+lite.dev`，即 [v1.3.1](release-v1.3.1.md) 采用的独立模式、独立认证密钥实现。速度与程序 SHA256 属于这次受测构建；正式附件另有自己的校验清单。

**结果：36/36 个文件通过接收端 SHA256 校验，共 2.25 GiB。** 按密码、方向和副路数配成 18 对，Lite 在每一对都更快，全文件速率是对应标准模式的 **1.48～3.79 倍**。排除首个 16 MiB 后，剩余 48 MiB 在 18/18 对中仍然更快。

| --- | ---: | ---: | ---: | ---: |
| Presto → PrestoLite | 16.6 → **46.2** | 18.1 → **34.5** | 16.5 → 43.9 | 17.7 → 31.6 |

## 方法

Windows amd64，IPv4 `127.0.0.1`，正常 TLS，`bbr3 / standard`。服务端忽略客户端带宽，客户端不设置带宽。每轮核对只连接一次且协商 `tx=0`。标准与 Lite 都使用**同一个无插桩二进制**；三对配置分别是 Presto / PrestoLite、NetFront / NetFrontLite（两副路）、NetFront / NetFrontLite（三副路）。

提前固定 A、B、C 三份测试密码，每份各测上传、下载；同密码、同方向、同副路数的两种模式相邻执行，轮换先后次序。每次都启动全新的客户端和服务端，通过真正的 TCP 转发传同一份 **64 MiB** 随机文件。文件在计时前生成；服务端 ACL 只允许本轮本机源站。接收应用在发出读请求前开始计时，到收满文件并更新 SHA256 时截止；双方另交换并确认摘要。

速率为十进制 Mbit/s。每次有四个连续的 16 MiB 窗口。若看启动后的速度，以后三段总字节除以其总耗时，不取三个速率的算术平均。相同密码在不同连接仍独立随机采样；这些数据描述这台机器和负载，不代表公网速度或外部识别率。

- 实测 Windows 程序 SHA256：`3eae114d659289dd684f0456b15bc8ea0b305147d7c744c3743757bc9700adb0`。
- 接收文件 SHA256：`c2b243dee8daaf6982f25fcce7392e7527bd3a6517c713b3f0ce8e07cab260f4`。
- 完整本地回执：`build/lite-modes-20261120/throughput/cases.json`，SHA256 `02ad4c2fa394068c1ec9599d4ca289c46426867fc12d53c2e88a1b38e721c23c`。

## 两端是否真的选中了同一模式

独立运行 17 组 CLI 对照。9 组正例均通过同一 TCP 流的两段内容校验，每组 72/72 个 UDP 回显完整，合计 **648/648**。其中 6 组是新程序选择标准 Presto、两副路 NetFront 或三副路 NetFront，分别与 v1.3.0 互换客户端/服务端；另 3 组是双方都明确选中相同 Lite 模式。相同密码下标准与 Lite 混配的 6 组，以及错误 CA、错误混淆密码的 2 组，均未建立应用连接。

另用真实 UDP socket 分别验证 NetFrontLite 的两、三副路：每条配置的副路都完成了双向路径验证，两组都在两个方向传过真实小帧。刻意阻断两条副路的用例仍经主路完成 240/240 次回显；被阻断副路没有被误认作已验证。这些计数来自功能负载，不是上面大文件的分流比例。

Windows 的混淆包回归、CLI / QUIC 封装上限定向测试、相关 `-race` 测试和 65 项 Python 测试通过。Linux amd64、arm64 开发程序完成交叉编译；上述运行数据均为 Windows 回环。

## 复现

在仓库根目录，使用支持两个新类型的程序与新的输出目录：

```sh
uv run --locked --offline python tests/network/lite_throughput.py --exe PATH_TO_CLI --output NEW_RESULTS
```

[`lite_throughput.py`](../tests/network/lite_throughput.py) 写入预定顺序、程序/测试文件摘要、每次实收字节、四段速度和汇总；保留失败样本。独立的[模式匹配与 v1.3.0 兼容验证](../tests/network/lite_interop.py)使用 `--old V1_3_0 --new PATH_TO_CLI --output NEW_INTEROP`。
